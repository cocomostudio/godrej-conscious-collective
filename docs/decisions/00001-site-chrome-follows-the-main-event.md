# Site chrome follows the main event, not the page's own event

The header, the footer, and the When and Where at the foot of a two-column page's sidebar read their date range, their Register Now button and their date/time line from the **main event**. Everything else event-derived on a page reads from the **resolved event** — the entry's own event, falling back to the main event, falling back to a hardcoded palette. Chrome is site-wide furniture rather than page content, so it advertises whichever event is currently running; the alternative, chrome following the resolved event, would leave a visitor arriving on an old page through an old link with no route to the event that is actually running.

## Consequences

⚠️ **Known problem, deliberately accepted and unmitigated.** On an archived page the chrome and the body disagree: a Conscious Collective 2025 session sits directly under a Register Now button for 2027, so the page appears to offer registration for the session being read. Suppressing or relabelling that button on archived entries was considered and declined, and the header's date range would still be wrong even if the button were fixed.

**The disagreement extends to colour, in the other direction.** The six `--ctx-*` colour variables are injected from the resolved event onto the page's outermost element, and the header and the footer sit inside that element — so the chrome advertises the main event in the resolved event's colours. A page belonging to a past or a future event shows a Register Now button for the event that is running, painted in the theme colour of the event the page is about. Separating the two would mean a second set of colour variables scoped to the chrome, doubling the mechanism to fix a mismatch that is already accepted one clause above. Declined on the same grounds, and recorded here so that the next reader does not take colour for an oversight.

**A third chrome surface joined later, in the sidebar.** A two-column page carries a second copy of the footer's When and Where, pinned to the bottom of the sidebar and fading out as the footer's own copy approaches. It follows the main event for the reason above, and because two copies of the same lines on one page that disagreed with each other would be worse than either of them being wrong. It is the only thing in the sidebar that does not follow the page, which is why the sidebar's glossary entry says so.
